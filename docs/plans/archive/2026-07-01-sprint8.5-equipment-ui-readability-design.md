# Sprint 8.5: Equipment & Loot UI Readability — Design

**Date:** 2026-07-01
**Scope source:** `docs/roadmap.md` Sprint 8.5
**Status:** Designed with autonomous defaults (user AFK at card-layout question); layout direction is the stat-pair-forward card. Revisable before implementation completes.

## Problem

The stat pair + AwakenedAbility model (2026-02-17 redesign) is illegible in the current UI:

1. `ItemDisplayData.StatSummary` flattens `GetTotalStatMods()` into one string ("CON +11  STR +3"): primary, secondary, and ability contributions are indistinguishable, and the ability's boost double-counts into the same numbers it should explain.
2. Abilities render as raw IDs ("iron_mind") because `AbilityTable` is a local variable in `GameManager.Awake()`: the UI cannot resolve names or descriptions.
3. No ability XP progress or gold level-up control exists anywhere; `GameManager.LevelUpAbility` has no UI.
4. Loot screen tiles are solid rarity-colored blocks with tiny centered text: no stats, no sprite, low contrast.
5. Nothing on the explore screen announces loot drops (`OnLootDropped` has no UI subscriber).

## Design

### Card layout: stat-pair-forward

One card design reused everywhere an item is listed:

```
┌─────────────────────────────────┐
│ ▌Fine Chain Shirt        Torso  │  name in rarity color, rarity edge stripe,
│ ▌ [sprite]                      │  slot top-right, item sprite left
│ ▌  CON +7        WIS +3         │  primary LARGE + stat color, secondary smaller/dimmer
│ ▌  ✦ Ironhide ●●○   CON +3     │  ability name, level pips (filled/max), potency
│ ▌  ⚖ 13          💰 45g   ▲ +4 │  score · sell value · context delta badge
└─────────────────────────────────┘
```

### Components

**1. Plumbing (Equipment + Managers assemblies)**
- `AbilityTable.GetById(string id)`: dictionary-backed lookup, null for unknown/null id
- `AbilityTable.FormatDescription(AbilityEntry, float potency)`: substitutes `{potency}` in the description template
- `GameManager.AbilityTable` public read-only property (the instance already created in `Awake()`)

**2. `ItemDisplayData` restructure (UI assembly)**
Replace the merged `StatSummary` with typed fields the card can lay out:
- Stat pair: `PrimaryStat`, `PrimaryValue`, `SecondaryStat`, `SecondaryValue`
- Ability block (all empty/zero when item has no ability): `AbilityName`, `AbilityDescription` (potency-substituted), `AbilityStat`, `AbilityPotency`, `AbilityLevel`, `AbilityMaxLevel`, `AbilityXpFraction` (0-1 toward next level, 1 at max)
- Existing: `DisplayName`, `SlotName`, `RarityName`, `RarityColor`, `Score`, `SellValue`, `Slot`, `Rarity`
- `FromItem(item, questLevel, abilityTable, economyConfig)`: ability table resolves names; economy config supplies XP threshold/growth for the fraction. Falls back gracefully (raw id, no bar) when either is null.

**3. `ItemCardBuilder` (new, UI assembly)**
Single code-built UGUI card factory replacing the three ad-hoc builders (`EquipmentDrawer.CreateItemRow`, `LootScreenController.CreateItemTile`, and the drawer's selected-slot fill logic). Options struct: show sprite, show delta badge (vs a comparison item), best tag, tap callback, compact height. Stat labels use `StatTypeColors.GetColor`. Matches the existing procedural-UI pattern (no prefabs, built at runtime).

**4. `LootScreenController`**
Grid of colored tiles → vertical scrolling card list (same cards as the drawer), sorted by score descending. Header (count/capacity) and Optimize All button unchanged. Cards show an upgrade arrow when the item is an upgrade for at least one roster character.

**5. `ItemDetailPanel`**
Keep the SerializeField shell (panel, name label, sell/close buttons, picker container) so `ExploreSceneBuilder` changes stay minimal; build the body procedurally (the character picker already is):
- Header: name in rarity color, "Rarity · Slot"
- Stat pair block: primary large with stat color, secondary below, smaller
- Ability block: name + level pips, description with current potency, XP progress bar with numeric fraction, **Level Up (cost g)** button wired to `GameManager.LevelUpAbility`; hidden when no ability, disabled when max level or unaffordable, cost from `AwakenedAbility.GoldCostToLevel` with EconomyConfig values
- Comparison: existing character picker, restyled with the shared delta badge treatment
- Footer: Sell button with value

**6. Loot drop feed (Explore screen)**
New `LootToastFeed` component subscribed to `GameManager.OnLootDropped`: stacked rows above the bottom nav, each "▲ Fine Chain Shirt · CON +7" in rarity color, fade+slide out after ~3s, max 3 visible (oldest evicted). Registered by `ExploreSceneBuilder`.

## Data flow

`EquipmentInstance` → `ItemDisplayData.FromItem(item, questLevel, gm.AbilityTable, gm.economyConfig)` → `ItemCardBuilder.Build(data, options)` / `ItemDetailPanel.Show(...)`. UI never touches `AbilityEntry` directly.

## Error handling

- Unknown ability id (stale save vs edited abilities.json): card shows the raw id, no description, XP bar hidden
- Null ability: ability row omitted entirely
- Missing sprite: existing tinted-placeholder behavior retained
- `LevelUpAbility` returning false (insufficient gold, max level): button state refreshed, no exception path

## Testing

EditMode (pure logic, no scene):
- `AbilityTable`: `GetById` hit/miss/null, `FormatDescription` substitution
- `ItemDisplayData`: stat pair fields populated; ability fields resolved via real `abilities.json`; `AbilityXpFraction` at 0, partial, and max level; no-ability and null-table fallbacks; double-count fix (primary/secondary values come from the pair, not `GetTotalStatMods`)

Manual play-test checklist (completes the stat redesign's deferred gameplay verification, roadmap exit criteria):
1. Drop loot while exploring → toast appears with correct name/rarity/primary stat
2. Loot screen cards legibly show pair + ability for every rarity
3. Detail panel: ability description with potency, XP bar advances over ticks, gold level-up increments level and potency
4. Drawer comparison deltas match `ItemComparer` expectations; equipping updates the paper doll

## Out of scope (YAGNI)

New art assets, prefab migration, party screen redesign beyond the shared card, triggered-ability display (data-modeled but not combat-resolved), sell-from-card shortcuts.
